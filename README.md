# 项目上下文管理系统（飞书版）

> 让**业务事实 → 产品文档 → 产品设计** 三层始终对齐：上游一变，下游自动亮灯。

## 一、这是个什么系统？

设计合稿（2026-11-09 定稿）：结构来自 Littlebird 的问题定义（一家制造企业产品团队的真实事故复盘，已匿名），
收敛机制来自 [Fieldstation](https://github.com/YihanYu115/Fieldstation) 的思路
（人声明关系，机器用确定性算法维护一致性），由 zcode 实现并经 Grokbot 移植合并。

> 核心原则：**事实卡是唯一口径源；文档和原型是投影，只引用事实 ID；
> 人声明依赖，机器算对齐并亮灯；口径要变必须新开卡、旧卡废弃、你批准后才现行。**

```
飞书多维表格（人在这干活）
 ├─ 业务事实表：事实卡（现行 / 待核实 / 已废弃，人工维护）
 ├─ 产品文档表：用「关联字段」声明依赖了哪些事实
 └─ 产品设计表：声明依赖了哪些文档 / 事实
        ↑ 读取                     ↓ 写回状态 + 原因
┌──────────────────────────────────┐
│ 对齐机器人（本项目，跑在你电脑上）      │
│ ✅已对齐 / ⚠️待核对 / ❌已失效        │
└──────────────────────────────────┘
```

## 二、状态口径（合稿）

**事实卡状态**（人维护，机器人不写）：`现行` / `待核实` / `已废弃`
- 新卡默认「待核实」，不是默认现行；只有拍板人批准后才变「现行」
- 发现冲突：旧卡也标「待核实」（逼下游亮灯），同时建候选新卡，AI 不裁决
- 口径变更 = 旧卡废弃 + 新卡现行 + 决策账记一条 D-xxx
- 兼容读取旧值：有效→现行、存疑→待核实、已失效→已废弃；
  **空值或未知值一律按「待核实」处理**（宁可错杀，不可放过）

**投影（文档/设计）对齐状态**（机器人算）：

| 顺序 | 情况 | 判定 |
|---|---|---|
| 1 | 依赖关系成环 | ⚠️ 待核对（先修复依赖结构） |
| 2 | 任一传递上游事实**已废弃** | ❌ 已失效（跨层传播到设计） |
| 3 | 上游丢失（被删除） | ⚠️ 待核对 |
| 4 | 勾了「已核对完毕」但上游有待核实 | ⚠️ 不入账，勾选保留 |
| 5 | 合法勾选（无丢失、无待核实） | ✅ 已对齐 + 新快照 + 清勾选 |
| 6 | 从未核对 / 依赖结构变化 / 上游指纹变化 / 有待核实事实 | ⚠️ 待核对 |
| 7 | 以上都没有 | ✅ 已对齐 |

**核对快照**：核对通过时机器人记下所有上游的「内容指纹」；之后任何一个上游内容变了
（指纹对不上），下游自动亮 ⚠️。指纹只含内容字段，机器人自己写的状态/原因/快照
不算在内，反复运行不会误报。

## 三、搭建步骤（保姆级，约 15 分钟）

### 第 1 步：飞书自建应用

1. [飞书开放平台](https://open.feishu.cn/app) → 创建企业自建应用 → 记下 **App ID / App Secret**
2. 权限管理 → 开通 **`bitable:app`（多维表格读写）**
3. 版本管理与发布 → **发布版本**（不发布权限不生效，这是最常见的坑）

> 如果你已经有自建应用，可直接复用，无需新建。

### 第 2 步：建测试多维表格

新建多维表格（建议名「上下文系统·测试台账」，**先不碰你的正式工作区**），
建 3 张数据表，**字段名一字不差**：

**表 1「业务事实」**

| 字段名 | 类型 | 说明 |
|---|---|---|
| 事实ID | 文本 | F-xxx，永久递增，永不复用 |
| 一句话陈述 | 文本（主字段） | 一句说清口径 |
| 状态 | 单选 | `现行` / `待核实` / `已废弃` |
| 来源 | 文本 | 一手记录位置（妙记/纪要/带日期对话），**禁止指向 PRD** |
| 发言人 | 文本 | 可选，如「客户负责人」 |
| 置信度 | 单选 | 可选：`客户亲口` / `推断` / `待确认`（不参与亮灯） |
| 创建日期 | 文本 | 可选，YYYY-MM-DD |
| supersedes | 文本 | 可选，被本卡取代的旧卡 ID |
| superseded_by | 文本 | 可选，取代本卡的新卡 ID |
| 关联决策 | 文本 | 可选，D-xxx |

**表 2「产品文档」**

| 字段名 | 类型 |
|---|---|
| 文档标题 | 文本（主字段） |
| 文档链接 | 超链接 |
| 依赖的事实 | **关联 → 业务事实表**（可多选） |
| 状态 | 单选：`已对齐` / `待核对` / `已失效`（机器人写） |
| 对齐原因 | 文本（机器人写） |
| 上次核对时间 | 文本（机器人写） |
| 核对快照 | 文本（机器人写，存 JSON） |
| 已核对完毕 | **复选框**（人工勾选） |

**表 3「产品设计」**

| 字段名 | 类型 |
|---|---|
| 设计名称 | 文本（主字段） |
| 原型链接 | 超链接（Figma 等） |
| 原型附件 | 附件 |
| 依赖的文档 | **关联 → 产品文档表**（可多选） |
| 依赖的事实 | **关联 → 业务事实表**（可多选） |
| 状态 / 对齐原因 / 上次核对时间 / 核对快照 / 已核对完毕 | 同表 2 |

### 第 3 步：把应用加进表格（容易漏！）

多维表格右上角「**···**」→「**更多**」→「**添加文档应用**」→ 添加你的应用。
不做这步必报「无权限」。

### 第 4 步：填配置

看浏览器地址栏：`https://xxx.feishu.cn/base/BBBBBB/?table=tblAAAA` →
`base/` 后面是 BASE_TOKEN，`table=` 后面是各表 ID（点不同表，地址栏会变）。

```bash
cp .env.example .env   # 然后编辑 .env 填入凭证和三个表 ID
```

### 第 5 步：安装依赖并自检

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python setup_check.py    # 全绿说明配置没问题
```

### 第 6 步：灌示例 + 演示剧本

```bash
.venv/bin/python seed_demo.py        # 灌入「通用基布判定」案例（阶段 C1）
.venv/bin/python align.py --dry-run  # 先看机器人想改什么
.venv/bin/python align.py            # 正式运行
```

**演示剧本**（亲手把口径变更走一遍）：

1. **C1 已失效**：seed 后直接跑 → 两份文档和原型全变 ❌（依据的 F-003 已废弃）
2. **C2 待核对**：表格里把两份文档「依赖的事实」从 F-003 改挂 F-007，再跑 → ⚠️
3. **C3 已对齐**：勾两份文档「已核对完毕」，再跑 → 文档 ✅、原型仍 ⚠️；
   再勾原型「已核对完毕」，再跑 → 全部 ✅
4. **加演 B 阶段**：把 F-003、F-007 都改「待核实」，再跑 → 全部 ⚠️，
   此时即使勾「已核对完毕」也不入账（待核实不能显示已对齐）

## 四、日常怎么用

| 你做了什么 | 机器人会做什么 |
|---|---|
| 登记新事实卡（默认待核实） | 依赖相关事实的下游亮 ⚠️ |
| 批准口径：新卡现行、旧卡已废弃 | 还挂旧卡的投影变 ❌；改挂新卡后变 ⚠️ |
| 修完投影、勾「已核对完毕」 | 下次运行入账恢复 ✅ |
| 原地修改现行卡的陈述（违规但手滑） | 指纹变化，下游照样亮 ⚠️（引擎给纪律兜底） |

```bash
.venv/bin/python align.py              # 手动跑一次
.venv/bin/python align.py --loop 60    # 每 60 分钟自动跑
.venv/bin/python align.py --dry-run    # 只看不算
```

群提醒（可选）：群设置 → 群机器人 → 自定义机器人 → webhook 填进 `.env` 的
`FEISHU_WEBHOOK_URL`，有待核对/已失效时自动发摘要。

## 四点五、云端部署（可选：Railway）

不想让机器人依赖个人电脑常开，可以部署到 Railway 这类平台长期运行（本项目实际就是这么跑的）：

- 启动命令写在 `Procfile`：`python -u align.py --loop 5`（每 5 分钟巡检一次）
- 凭证放在平台的环境变量里（本地 .env 不上传 git）
- 更新流程：本地改完 → `git push`（留档）→ `railway up --detach --yes`（重新部署）

## 五、角色边界（合稿）

- **事实管理员**：起草事实卡、维护来源，**不能**把卡批准为现行
- **产品设计员**：写投影、声明依赖、勾核对，**不能**擅自定口径
- **拍板人（你）**：唯一能把卡批准为「现行」的人
- 机器人只写 4 个字段（状态/原因/上次核对时间/核对快照）+ 清勾选，
  不改事实、不改依赖边

## 八、FAQ

**Q：报"无权限"？** ① 应用权限 `bitable:app` 已开通且**版本已发布**；
② 表格「···」→「更多」→「添加文档应用」做了吗。

**Q：机器人会改坏数据吗？** 只写投影表 4 个字段 + 清勾选；事实表整个不写。

**Q：决策账（D-xxx）在哪记？** v1 先在事实卡的「关联决策」字段里引用编号，
决策账正文（append-only 文档）放在团队知识库侧，属工作区建设，不在本仓库范围。

**Q：和正式工作区什么关系？** 本仓库的机器人只认 `.env` 指向的表格。
测试台账跑通后，把 `.env` 换成正式表的 ID 即可切换，代码零改动。
